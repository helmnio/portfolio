1 · What it needed

What the site had to do.

A buyer might arrive from a search, a location or one specific development. They need to find homes near them, see which developments are selling or coming soon, compare house types and plots, and register interest without having to work out which plot or site they are asking about.

Plot and site data came from the client’s own system, through a separate integration that writes it into WordPress. My side was the theme: how that data is read, shown, searched and attached to enquiries, and how the team maintains it.

2 · What a visitor can do

The site in use.

  • Search from the homepage by location or postcode, or browse developments on a map or as a list, with a switch for forthcoming developments.
  • On a development page, see the key facts at a glance (plots available, prices from, bedroom range), contact the sales team, register interest or download a brochure, and move between Overview, Homes, The Site and Local area.
  • See a development’s house types in a grid or list, grouped by phase (for example one phase available now and another coming soon), each with a from-price, type, bedrooms and bathrooms.
  • Open a house type to see its plots and their availability, then register interest in a specific plot.
  • Work out stamp duty for a single property, an additional property or a first-time purchase.

3 · What I built

What I built, and how.

Developments, house types and plots as linked content

Developments are their own content type. House types and individual plots are Property Hive properties, and plots are linked to their house type and to a development through ACF relationships. The theme walks those links to answer questions such as “how many plots are left?” in one place, so every card and listing agrees.

Listing data worked out once

A single function builds everything a development card needs: the lowest price across its homes, the bedroom range (written as “2 to 4-bedroom homes”), its status and address. It only shows “plots available” when ten or fewer remain, so the number is useful rather than noise, and falls back to “Prices TBC” when data is missing. It reads the newer plot records and, where a house type still uses the older plots repeater, falls back to that, so both kinds of content display correctly.

Making inconsistent source data safe to display

Plot numbers from the source system often carry leading zeros, so “014” and “14” have to match for lookups but display in a readable form. Availability labels needed the same care: “available”, “available now” and “reserve now” all count as available. I put both into single helper functions (a display form and a matching key) so cards, plot lists and forms all agree.

Search that understands places and homes

Development search uses FacetWP with Google Maps and proximity search. A custom indexer copies each development’s home details (bedrooms and home types) onto the development, so searching for three-bedroom homes finds developments that have one. When a typed location is really a county, the visitor is sent to that county’s results instead of a radius search. Autocomplete is limited to UK results, the map caps the number of results, and forthcoming developments are filtered separately from those on sale.

Interest forms that know what the visitor is looking at

The interest forms are Gravity Forms. The theme works out the development or plot from the page, fills the option lists dynamically, and sets a hidden field to the development’s site code (falling back to the page title) for the sales team’s system. Whether someone can register interest depends on the plot’s availability, and entries are formatted so they read clearly in the admin. The brochure form has its own confirmation.

Pages that only organise the site

Some pages exist only to hold a menu or breadcrumb level. A “no page” switch turns them into labels: the menu item loses its link and is marked disabled for assistive technology, and the breadcrumb shows the label without a link. I also corrected missing breadcrumb markup for developments, homes and team pages.

A stamp duty calculator editors can maintain

The calculator’s tax bands, rates and buyer types are fields in the block. An editor types a band the way it reads (“£125k to £250k”), and the theme works out the threshold from the label, understanding “k”, “m” and “rest over”. If a label cannot be read, that row falls back to the default band, and with nothing entered the defaults apply, so a rate change does not need a developer.

4 · For the editors

What the team can do without a developer.

  • Long descriptions that feed the Rightmove export have a character limit. The theme warns after saving rather than blocking publishing.
  • The property list can be filtered by development, and the parent-house-type picker shows which development each option belongs to.
  • Each development defines its own phases, named or defaulting to “Phase 1, 2…”. Plot records inherit their phase from the house type, so the field is hidden on them.
  • A Property Blocks tab sits inside the Property Hive editor, so page content for a home lives with the home.
  • Only one post can be sticky at a time. That post becomes the featured article and is left out of the list below it.

5 · Decisions

Choices worth explaining.

Warn, don’t block

Problem

Rightmove may truncate long descriptions, but stopping an editor from saving would hold up publishing.

Approach

The limit is checked during ACF validation, the page still saves, and the warning appears on the next screen.

Trade-off

It is guidance rather than enforcement, so an editor can still leave an over-length description.

Normalise data once, in helpers

Problem

Plot numbers and availability labels arrive in slightly different forms depending on where they came from.

Approach

A small set of helpers produces the display value and the matching key, and every template uses them.

Take plots off the site when they leave the market

Problem

A plot that is sold or withdrawn can linger in search results or on a bookmarked link.

Approach

A template redirect checks whether the plot is public on the website and returns a 404 if not, except in preview.

Trade-off

Links to a plot stop working as soon as it goes off market.
